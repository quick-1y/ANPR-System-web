# Аутентификация и управление пользователями

## Общее

Все API-эндпоинты, кроме `/api/health` и `POST /api/auth/login`, требуют валидный JWT-токен. Токен получается через вход с логином и паролем.

---

## JWT-токены

- Получается через `POST /api/auth/login`.
- Передаётся в заголовке `Authorization: Bearer <token>` или query-параметром `?token=<jwt>` (используется для SSE и MJPEG-стримов).
- Срок жизни по умолчанию: 8 часов (480 минут). Настраивается администратором в UI (Настройки → Безопасность, ключ `auth.token_ttl_minutes` в `app_settings`, границы 5–43200 минут) и действует со следующего входа: уже выданные токены живут до своего `exp`.

---

## Роли

В системе три роли:

| Роль | Описание |
|---|---|
| `superadmin` | Технический аккаунт без строки в `users`: логин и пароль заданы окружением (`SUPERADMIN_PASSWORD`), проверяются заново при каждом входе. Обходит все проверки разрешений. Имеет неявный доступ к контроллерам, глобальным настройкам, экспорту/бэкапу данных и debug-эндпоинтам. Не может быть назначена ни при создании, ни при редактировании обычных пользователей через API или UI (`app/api/superadmin.py`). |
| `admin` | Может иметь любые разрешения, включая `tab:settings`, которое открывает доступ к управлению пользователями. |
| `operator` | Не может иметь разрешение `tab:settings`. Доступ ограничен вкладками, явно указанными в разрешениях. |

---

## Разрешения

Разрешения хранятся как JSONB-массив строковых ключей в записи пользователя.

| Ключ | Название | Описание |
|---|---|---|
| `tab:obs` | Наблюдение | Доступ к вкладке live-наблюдения |
| `tab:journal` | Журнал | Доступ к журналу событий |
| `tab:clients` | Клиенты | Доступ к вкладке клиентов и списков номеров |
| `tab:zones` | Зоны | Доступ к вкладке зон и связанной функциональности |
| `tab:settings` | Настройки | Доступ к вкладке настроек (без debug-раздела) и управлению пользователями; операторам не может быть назначено |

`superadmin` проходит все проверки разрешений автоматически. Пользователи с ролью `admin` получают разрешения явно при создании или редактировании.

---

## Сводка по уровням доступа

| Что запрашивается | Требование |
|---|---|
| Health check, вход | Публичный доступ — токен не нужен |
| Все остальные эндпоинты | Валидный JWT (любой активный пользователь) |
| Управление пользователями | Разрешение `tab:settings` (или роль `superadmin`) |
| Глобальные настройки и список стран | `tab:settings` (или роль `superadmin`) |
| Контроллеры, данные, debug | Только роль `superadmin` |

## Технический аккаунт суперадмина

Суперадмин не создаётся и не хранится — он определён целиком переменными окружения и не имеет строки в таблице `users`. `POST /api/auth/login` с логином `superadmin` перехватывается до обращения к БД (`_login_superadmin` в `app/api/routers/auth.py`, `app/api/superadmin.py`).

| Поле | Значение |
|---|---|
| Логин | `superadmin` (фиксированный, не настраивается) |
| Пароль | значение `SUPERADMIN_PASSWORD` из `.env`, проверяется заново при каждом входе; при пустой переменной — `1234` |

**Смена пароля** — правка `SUPERADMIN_PASSWORD` в `.env` и перезапуск контейнера; UI-эндпоинта для этого нет (`PUT /api/users/{id}/password` требует строку в `users`, у суперадмина её нет). **Перед использованием в production обязательно задайте `SUPERADMIN_PASSWORD`.** При `APP_ENV=production` незаданная переменная прерывает запуск, поэтому пароль `1234` в production не действует.

Поле `warn_default_password: true` в ответе на вход сигнализирует, что `SUPERADMIN_PASSWORD` не задан и в силе резервный пароль `1234`.

Строка `login='superadmin'` в `users`, оставшаяся от версии, где суперадмин ещё был обычным пользователем БД, больше не используется для входа (перехватывается раньше) и не удаляется автоматически — при обнаружении такой строки при старте пишется предупреждение в лог.

## Web UI — вход и выход

- При открытии страницы, если в `localStorage` нет валидного токена (`anpr_token`), отображается экран входа (`#login-overlay`).
- После успешного входа JWT сохраняется в `localStorage` под ключом `anpr_token`; данные пользователя хранятся в `state.currentUser`.
- В правом углу topbar отображается логин текущего пользователя и кнопка «Выход».
- Выход очищает `anpr_token` из `localStorage` и перезагружает страницу.
- Все API-запросы из UI (включая SSE и MJPEG-стримы) передают JWT через `Authorization: Bearer` или `?token=`.

## Auth API endpoints

| Метод | URL | Доступ | Описание |
|---|---|---|---|
| `POST` | `/api/auth/login` | Публичный | Аутентификация по логину + паролю; возвращает JWT и данные пользователя |
| `POST` | `/api/auth/logout` | Авторизованный | Фиксирует выход в аудит-лог; клиент удаляет токен |
| `GET` | `/api/auth/me` | Авторизованный | Возвращает текущего пользователя (роль, разрешения) |
| `GET` | `/api/permissions/available` | `tab:settings` | Возвращает список доступных ключей разрешений с метаданными |

**Защита от брутфорса:** `POST /api/auth/login` допускает не более `auth.login_rate_limit_attempts` неудачных попыток (по умолчанию 5) за окно `auth.login_rate_limit_window_seconds` (по умолчанию 60 с) с одного IP; политика настраивается в UI и читается при каждой проверке, без перезапуска. Счётчик сбрасывается при успешном входе; при превышении возвращается `HTTP 429`.

## Управление пользователями

Все эндпоинты управления пользователями требуют разрешение `tab:settings` (или роль `superadmin`).

| Метод | URL | Описание |
|---|---|---|
| `GET` | `/api/users` | Список пользователей (аккаунт `superadmin` не отображается) |
| `POST` | `/api/users` | Создать пользователя (только роли `admin` или `operator`) |
| `GET` | `/api/users/{id}` | Получить пользователя по ID |
| `PUT` | `/api/users/{id}` | Обновить роль, разрешения или статус активности |
| `PUT` | `/api/users/{id}/password` | Сменить пароль (admin меняет любому; пользователь — только свой) |
| `DELETE` | `/api/users/{id}` | Деактивировать пользователя (мягкое удаление, `is_active = false`) |

Пользователи никогда не удаляются физически.

**Защита от самоблокировки:** нельзя деактивировать собственную учётную запись. Отдельной защиты «последнего superadmin» больше нет — суперадмин не имеет строки в `users`, и эти эндпоинты не могут её достичь; `role` в `PUT /api/users/{id}` не принимает значение `superadmin` (см. «Роли» выше).

---

## Web UI — управление пользователями

Доступно в разделе **Настройки → Пользователи** (отображается пользователям с разрешением `tab:settings`).

- Список: логин, роль (АДМ / ОПЕ), статус активности.
- Создание: логин, пароль, роль, разрешения по вкладкам.
- Редактирование: роль, разрешения, переключатель активен/неактивен, смена пароля.
