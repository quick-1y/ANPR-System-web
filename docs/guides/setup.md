# Деплой и конфигурация

## Требования

- Docker Engine 24+
- Docker Compose v2+
- Файлы ML-моделей:
  - `anpr/models/yolo/` — модель детекции YOLOv8
  - `anpr/models/ocr_crnn/` — модель распознавания CRNN

---

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/quick-1y/ANPR-System-v0.8_web
cd ANPR-System-v0.8_web
```

### 2. Создать и настроить `.env`

```bash
cp .env.example .env
```

Обязательно задать перед запуском в production:

```env
APP_ENV=production
JWT_SECRET_KEY=<случайная строка 32+ байта>
POSTGRES_PASSWORD=<надёжный пароль>
SUPERADMIN_PASSWORD=<пароль технического суперадмина>
```

При `APP_ENV=production` запуск прерывается (`SystemExit`), если `JWT_SECRET_KEY` остался дефолтным или короче 32 байт, либо не задан `SUPERADMIN_PASSWORD`. В любом другом окружении те же проверки только пишут предупреждение в лог и запуск продолжается.

**Если `SUPERADMIN_PASSWORD` не задан, суперадмин входит с паролем `1234` (см. шаг 5) — задайте `SUPERADMIN_PASSWORD` как можно скорее.** Этот пароль одинаков в каждой установке и указан в документации и в тестовых фикстурах: оставленным без изменения он даёт полный доступ (включая бэкап/восстановление БД) любому, кто знает URL установки.

### 3. Собрать и запустить

```bash
docker compose up -d --build
```

Поднимаются четыре сервиса: `nginx`, `api`, `retention_worker`, `postgres`.

### 4. Проверить готовность

```bash
curl http://localhost:8080/api/health
curl http://localhost:8080/worker/health
```

Оба должны вернуть `200 OK`.

### 5. Открыть Web UI

Перейти в браузере на **http://localhost:8080**

Интерфейс использует системные шрифты браузера и увеличенную минимальную кегельную сетку, поэтому дополнительные файлы шрифтов устанавливать не нужно. Для операторов со слабым зрением можно дополнительно увеличить масштаб страницы штатными средствами браузера.

Логин: `superadmin`, пароль — значение `SUPERADMIN_PASSWORD` из `.env` (если переменная пуста — `1234`; **задайте её как можно скорее**, см. предупреждение на шаге 2). Суперадмин не хранится в БД — это технический аккаунт, определяемый окружением, поэтому изменение `SUPERADMIN_PASSWORD` действует сразу после перезапуска контейнера, в отличие от значений, которые раньше «застывали» при первом создании строки в `users`.

### 6. Обновление и сброс

```bash
# Пересборка с новым кодом
docker compose build --no-cache && docker compose up -d
```
```bash
# Остановка
docker compose down
```
```bash
# Полный сброс (удаляет все данные и volumes)
docker compose down -v
```

## Сервисы

Docker Compose запускает четыре сервиса:

| Сервис | Описание | Внутренний адрес |
|---|---|---|
| `nginx` | Reverse proxy — единственная публичная точка входа | `HTTP_PORT` (по умолчанию `8080`) |
| `api` | FastAPI + Web UI + channel runtime | `api:8080` |
| `retention_worker` | Retention, очистка, экспорт | `retention_worker:8092` |
| `postgres` | PostgreSQL 16 с init-схемой | `postgres:5432` (только внутри сети) |

Все переменные задаются в `.env` (скопировать из `.env.example`):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HTTP_PORT` | `8080` | Порт nginx на хосте |
| `POSTGRES_DB` | `anpr` | Имя базы данных PostgreSQL |
| `POSTGRES_USER` | `anpr` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | `anpr` | Пароль PostgreSQL |
| `POSTGRES_PORT` | `5432` | Порт, публикуемый контейнером PostgreSQL на хосте |
| `POSTGRES_DSN` | `postgresql://anpr:anpr@postgres:5432/anpr` | Полный DSN для подключения приложения |
| `JWT_SECRET_KEY` | `anpr-default-secret-change-me` | Секрет подписи JWT — **обязательно заменить перед деплоем** |
| `APP_ENV` | `docker` | Режим окружения. `production` включает строгие проверки секретов при старте; любое другое значение — только предупреждения |
| `SUPERADMIN_PASSWORD` | *(пусто)* | Пароль технического суперадмина (нет строки в `users`, читается заново при каждом входе). Обязателен при `APP_ENV=production`; при пустом значении используется `1234` |
| `LOG_LEVEL` | `INFO` | Bootstrap-уровень логирования (`ALL`, `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`): действует с запуска процесса до первого чтения настроек из БД, затем уровень берётся из `app_settings` (`logging.level`, настраивается в UI) |
| `ANPR_LOGS_DIR` | `/app/logs` | Каталог файлов логов (точка монтирования `logs_data`); из UI не меняется |
| `ANPR_MEDIA_DIR` | `data/screenshots` | Каталог скриншотов и экспорта (точка монтирования `media_data` → `/app/data`); из UI не меняется |
| `ANPR_YOLO_MODEL_PATH` / `ANPR_OCR_MODEL_PATH` | `anpr/models/...` | Пути к весам моделей внутри образа. Если файла нет, приложение не стартует и называет переменную в ошибке |
| `ANPR_DEVICE` | `cpu` | Устройство инференса (`cpu`, `cuda`) |
| `POSTGRES_POOL_MIN` / `POSTGRES_POOL_MAX` | `2` / `10` | Границы пула соединений PostgreSQL |
| `ANPR_IO_POOL_WORKERS` | `2` | Число потоков записи скриншотов |
| `CORS_ALLOWED_ORIGINS` | *(пусто)* | Список origin'ов через запятую, которым разрешён кросс-origin доступ к API из браузера (сторонние дашборды, интеграции). Пусто = кросс-origin доступ из браузера отключён; встроенный веб-интерфейс отдаётся с того же origin и не затрагивается. На серверные интеграции (без браузера, со своим токеном) не влияет — CORS проверяется только браузером |
| `OMP_NUM_THREADS` | `2` | Лимит потоков PyTorch/OpenMP — предотвращает перегрузку CPU |
| `MKL_NUM_THREADS` | `2` | Лимит потоков MKL |
| `OPENBLAS_NUM_THREADS` | `2` | Лимит потоков OpenBLAS |

## Конфигурация

Конфигурация разделена по тому, кто ею владеет; файла настроек нет.

| Что | Где хранится | Как менять |
|---|---|---|
| Развёртывание: секреты, DSN, порты, каталоги, пути к весам, устройство, лимиты пулов, CORS | переменные окружения (`.env`, таблица выше) | правка `.env` и перезапуск контейнеров |
| Операционные настройки инстанса: переподключение, retention, уровень и срок хранения логов, список стран, порог детектора, политика аутентификации, зона отображения времени, серверный debug-флаг | таблица `app_settings` в PostgreSQL | UI: **Настройки** (значения действуют без перезапуска; список стран и порог детектора автоматически перезапускают обработчик, интерфейс об этом сообщает) |
| Каналы, ROI, OCR-пороги каналов, контроллеры, зоны, списки, пользователи | таблицы PostgreSQL | UI |
| Тема, стиль, фиксация левой панели, debug-панель, метрики каналов, размер видеосетки, порядок плиток | `localStorage` браузера — нет серверного владельца, не переносится на другое рабочее место | UI: кнопка **☰ Мои предпочтения** (тема, стиль) и переключатель темы в верхней панели, кнопка закрепления в боковой панели, чекбоксы в Настройки → Разработка — сохраняются сразу |

Отсутствие строки в `app_settings` означает значение по умолчанию из реестра (`config/registry.py`), поэтому таблица не требует наполнения. `TZ=UTC` в контейнерах; зона отображения влияет только на представление времени (интерфейс, экспорт CSV/ZIP), не на хранение.

Контракты OCR и YOLO detector не являются runtime-настройками и зафиксированы в `anpr/model_config.py`: для OCR это размер входа `32×128` и алфавит `0123456789ABCEHKMOPTXY`, для detector — `bbox_padding_ratio=0.08`, `min_padding_pixels=2`. Менять их безопасно только вместе с проверенными/переобученными моделями.

### Резервная копия настроек

**Настройки → Система и данные → Экспорт настроек** скачивает JSON-дамп явно заданных значений `app_settings` (не значений по умолчанию). Импорт принимает только такой дамп: неизвестный ключ или недопустимое значение отклоняют файл целиком, ничего не записывая; после импорта параметры, которых нет в файле, возвращаются к значениям по умолчанию. Старые YAML-файлы настроек не принимаются. Резервная копия базы данных содержит бизнес-данные и **не** содержит `app_settings`: восстановление БД не перезаписывает конфигурацию инстанса, а восстановление настроек не затрагивает данные.

### Первый запуск на чистой базе

1. Скопировать `.env.example` в `.env`, задать `JWT_SECRET_KEY` (32+ байта) и `SUPERADMIN_PASSWORD`; для боевой установки — `APP_ENV=production` (запуск с дефолтным секретом тогда невозможен).
2. `docker compose up -d --build`. PostgreSQL создаёт полную схему из `database/postgres/schema.sql`; таблица `app_settings` пуста, и это нормально — все настройки работают на значениях по умолчанию.
3. Войти как `superadmin` со значением `SUPERADMIN_PASSWORD`, заданным на шаге 1 (сменить его позже можно только правкой `.env` и перезапуском контейнера — см. `docs/technical/auth.md`).
4. **Настройки → Время → Часовой пояс**: выбрать зону объекта. Пока зона не выбрана явно, каждый пользователь видит время своего компьютера (в настройках висит уведомление); выбор вступает в силу для всех без перезапуска.
5. Остальные параметры при необходимости изменить (страны, retention, политика входа).

### Переход с предыдущей версии

Файл `config/settings.yaml` больше не читается, миграции и импорта нет (политика проекта: чистая замена, без слоёв совместимости). **До обновления** выпишите значения из старого файла и введите их заново в UI:

| Из старого файла | Куда вводить |
|---|---|
| `interface.style`, `interface.theme` | не переносятся: тема и стиль теперь состояние этого браузера (Мои предпочтения), без сервера и без учётной записи |
| `time.timezone` (`UTC±HH:MM`) | Настройки → Время → Часовой пояс (теперь IANA, например `Europe/Minsk`); пока зона не выбрана, показывается время компьютера пользователя |
| `plates.enabled_countries` | Настройки → Номера |
| `reconnect.*` | Настройки → Переподключение (внимание: периодическое переподключение по умолчанию выключено) |
| `storage.*` retention (`auto_cleanup_enabled`, `*_retention_days`, `max_screenshots_mb`, `cleanup_interval_minutes`) | Настройки → Хранение |
| `logging.level`, `logging.retention_days` | Настройки → Логи |
| `models.*`, `storage.screenshots_dir`, `storage.logs_dir` | переменные `ANPR_*` в `.env` |
| `debug.*` | серверный `video_output_enabled` — Настройки → Разработка; остальное — состояние браузера (localStorage) |

Из `.env` удалите `SETTINGS_PATH`, `DEBUG`, `JWT_EXPIRATION_MINUTES` (срок сессии теперь в Настройки → Безопасность) и добавьте `ANPR_*` из `.env.example`. Каталог `./config` больше не монтируется в контейнеры; локальный `config/settings.yaml` можно удалить после переноса значений.

### Откат

Откат — это возврат **всего проекта** к заведомо рабочей ревизии git, а не обратная миграция:

```bash
git log --oneline            # найти известную рабочую ревизию (записать её до обновления: git rev-parse HEAD)
docker compose down          # без -v: данные и volumes сохраняются
git checkout <ревизия>       # или git revert диапазона коммитов
docker compose up -d --build
```

Схема БД при переходе от `settings.yaml` менялась добавлением (`app_settings`, `app_settings_revision`), поэтому предыдущая ревизия работает на той же базе; она снова читает свои настройки из `config/settings.yaml` (он нужен ей на месте — не удаляйте файл, пока не убедитесь, что новая версия вас устраивает). Значения, введённые в UI новой версии, в старую не переносятся. Резервную копию БД, сделанную новой версией, нельзя восстановить в базу старой схемы.

Позже колонка `users.preferences` была добавлена, а затем полностью убрана (личные UI-предпочтения переехали на `localStorage`, см. [`docs/roadmap/configuration-architecture.md`](../roadmap/configuration-architecture.md)) — это единственное удаление в схеме на сегодня. Она не ломает откат: код старее удаления пересоздаёт колонку при следующем запуске (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`) и просто не найдёт в ней новых значений; код новее удаления работает и с базой, где колонка ещё физически присутствует — он её больше не читает и не пишет.

## Аппаратные контроллеры

Контроллеры настраиваются через API и хранятся в PostgreSQL. Описание реализации — в [`docs/modules.md`](../technical/modules.md).

### Конфигурация контроллера

Каждый контроллер содержит:
- имя, тип (`DTWONDER2CH`), сетевой адрес и пароль;
- два реле, каждое с режимом срабатывания и опциональным хоткеем.

Удаление контроллера, привязанного к каналу, возвращает ошибку.

### Режимы фильтрации для автосработки реле

Привязка контроллера к каналу задаётся через `controller_id`, `controller_relay` (0 или 1), `list_filter_mode` и `list_filter_list_ids`. Перед отправкой команды система проверяет правила фильтрации.

| `list_filter_mode` | Поведение |
|---|---|
| `all` | Реле срабатывает для любого номера, кроме номеров из black list |
| `whitelist` | Реле срабатывает только для номеров из списков типа `white`; black list блокирует |
| `custom` | Реле срабатывает только для номеров из выбранных списков; black list блокирует |

Приоритет black list абсолютный во всех режимах.

### Фильтр направления движения (`controller_direction_filter`)

Применяется дополнительно к фильтру списков — оба условия должны выполниться.

| Значение | Поведение |
|---|---|
| `both` | Направление не учитывается (по умолчанию) |
| `approaching` | Команда отправляется только при движении ТС в сторону камеры |
| `receding` | Команда отправляется только при движении ТС от камеры |

Если направление не удалось определить (`UNKNOWN`), команда при значениях `approaching` или `receding` не отправляется.

### Режимы реле

| Режим | Поведение |
|---|---|
| `pulse` | Мгновенный импульс (таймер фиксирован: 1 с) |
| `pulse_timer` | Импульс с таймером (настраиваемый, ≥ 1 с) |

### Хоткеи реле

Хоткей задаётся на конкретное реле. Нажатие в Web UI отправляет тестовую команду контроллеру. Хоткей блокируется при фокусе в поле ввода или при удержании клавиши. Дубликаты хоткеев в одном контроллере запрещены валидацией API.

## Хранение данных

### PostgreSQL

Все события, списки номеров, клиенты, каналы, контроллеры и пользователи хранятся в PostgreSQL через `POSTGRES_DSN`.

**Ключевые таблицы:**

| Таблица | Основные поля |
|---|---|
| `zones` | `id`, `name`, `capacity` |
| `events` | `id`, `time`, `channel_id`, `plate`, `plate_display`, `country`, `confidence`, `source`, `frame_path`, `plate_path`, `direction`, `client_id`, `zone_id`, `time_entry`, `time_exit` |
| `lists` | `id`, `name`, `type`, `is_deleted` |
| `clients` | `id`, `list_id` *(nullable — клиент может существовать без списка)*, `plate`, `plate_normalized`, `last_name`, `first_name`, `middle_name`, `phone`, `car`, `comment`, `is_deleted` |
| `users` | `id`, `login`, `password` (bcrypt), `role`, `permissions` (JSONB), `is_active`, `created_at`, `updated_at` |

**Зоновые поля событий:**  
`zone_id > 0` — ТС находится в зоне; `zone_id = 0` — ТС вне парковки (системный sentinel «Вне парковки»); `zone_id IS NULL` — зона не используется. `time_entry` и `time_exit` фиксируют моменты въезда и выезда. Значение `zone_id` всегда соответствует `zone_after_id` канала, обработавшего событие.

**Зоновые поля каналов:**  
`zone_before_id` — зона, в которой ТС находится до прохождения канала; `zone_after_id` — зона после прохождения; `zone_channel_type` — тип канала (`entry` / `exit` / `null`). Значение `0` в обоих полях означает «Вне парковки».

**Индексы:** `(time DESC, id DESC)` по событиям; `plate_normalized` и `(list_id, plate_normalized) UNIQUE WHERE is_deleted = FALSE` по клиентам; `(zone_id) WHERE zone_id IS NOT NULL AND zone_id > 0 AND time_exit IS NULL` для подсчёта занятости зоны.

### Медиа и экспорт

- Скриншоты и кропы номеров сохраняются в каталог `ANPR_MEDIA_DIR`.
- CSV и ZIP-экспорт формируются в памяти и отдаются браузеру напрямую как файл для скачивания.
- Bundle export упаковывает CSV и доступные медиафайлы в ZIP.

Настройка политики retention (автоочистка, лимиты хранилища) — в разделе **Настройки → Данные** в Web UI.
